# Deploying: Render (web service) + MongoDB Atlas (database)

One web service, one database, one instance. The service must **not** be scaled out: the board cache, the live-update streams and the rate limits live in process memory (see DECISIONS D25).

## 1. Atlas

1. Cluster: the free M0 cluster you already have. Create a database user with read and write access (Database Access). Use a long random password; avoid `@ : / ?` in it, or URL-encode them.
2. Network Access: allow `0.0.0.0/0`. Render's free instances have no fixed outbound address, so an allow-list of one IP is not possible. The protection is the long password and TLS. Say this openly in the design doc.
3. Connection string: Connect, Drivers, copy the `mongodb+srv://` string and put the database name before the `?`:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/teams_seed?retryWrites=true&w=majority`
   The database is called `teams_seed` on purpose: the seed script refuses to wipe a database whose name contains neither `dev` nor `seed`.

## 2. Seed the Atlas database (from the Codespace)

A leading space keeps the command, and the password in it, out of shell history. A shell variable overrides `.env`.

```
 MONGODB_URI='mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/teams_seed?retryWrites=true&w=majority' npm run seed
```

Expect `seeded 10000 users, 2000 teams, ...` and `invariants ok`. It can take a minute or two because M0 throttles operations. Seeded users have no password, so nobody can sign in as them; the seeded teams exist to give the board realistic volume. To demo joining, register two accounts: one creates a team and reads its invite code, the other joins with it.

## 3. Render

1. New, Blueprint, pick this repository. Render reads `render.yaml` (free plan, build `npm ci --include=dev && npm run build` (Vite builds the React app into `dist/`), start `node src/server.js`, health check `/healthz`). Pick the region closest to your Atlas cluster.
2. When asked, set `MONGODB_URI` to the string from step 1. `SESSION_SECRET` is generated by Render.
3. Wait for the first deploy (3 to 5 minutes). Logs should say `listening on 10000 (board cache ttl 2000 ms)`.

Without the blueprint: a Web Service with the same build and start commands and the variables below.

| Variable | Value | Why |
|---|---|---|
| `MONGODB_URI` | the Atlas string | the database |
| `SESSION_SECRET` | 32+ random characters | signs session tokens; rotating it signs everyone out |
| `NODE_ENV` | `production` | session cookies get the `Secure` flag |
| `TRUST_PROXY` | `1` | Render is one proxy in front, so `req.ip` is the real client and rate limits work |
| `NODE_VERSION` | `22` | pin the runtime |

## 4. Smoke test

```
BASE_URL=https://<your-service>.onrender.com node scripts/smoke.js
```

It registers two users, creates a team, checks the live stream delivers an event through Render's proxy, joins by invite code, and reads the board and the audit log. It must end with `SMOKE PASSED`. This is a check that the deployment works, not a load test: the free instance has a small share of a CPU and Atlas M0 allows about 100 operations per second, so load numbers measured against it would describe the limits of the free tiers. Load tests are run locally (PERFORMANCE.md).

## 5. Cold starts (read this before the judging window)

A free instance sleeps after about 15 minutes without traffic and takes roughly 30 to 60 seconds to wake. A judge who opens the link cold may think it is broken. Options, cheapest first:
- Before submitting, and again before the video, open the site and run the smoke test to warm it.
- A free uptime monitor (for example UptimeRobot) requesting `/healthz` every 10 minutes keeps it awake. A single service running all month fits in Render's free instance hours.
- Switch the service to the paid Starter plan for the judging window, then switch back.

Also expect sign-up and login to take noticeably longer than locally: scrypt is deliberately expensive and the free instance has a small CPU share.

## 6. Troubleshooting

| Symptom | Likely cause |
|---|---|
| `MongoServerSelectionError` in the logs | Atlas Network Access does not allow `0.0.0.0/0`, or the password in the URI has an unescaped special character |
| `SESSION_SECRET must be set` | the variable is missing or shorter than 32 characters |
| Sign-in succeeds but the next request is 401 | `NODE_ENV` is not `production`, or the site is opened over plain http, so the `Secure` cookie is dropped |
| Rate limit hits for everyone at once | `TRUST_PROXY` is not set, so every request appears to come from the proxy |
| The stream connects but no events arrive | a proxy is buffering; the app sends `X-Accel-Buffering: no` and a heartbeat every 25 s, so check for another proxy or CDN in front |
| Everything is slow after a quiet period | the instance was asleep (section 5) |

## 7. Rollback

Render keeps previous deploys: open the service, Events, and roll back to the last good one. The database is not migrated by deploys; indexes are created idempotently at startup.
